<a name="article-23001"></a>

### 第 23001 條【Interface 債務】

已公開之 Interface 應依文件契約解釋，不得依作者未公開之內心意思解釋。

<a name="article-23002"></a>

### 第 23002 條【TODO 所有權】

無負責人之 TODO 得經協議分配，不得自動由最新入職者繼承。

<a name="article-23003"></a>

### 第 23003 條【Snippet 借用】

借用之 Snippet 即使更改變數名稱，仍應履行適用之署名義務。

<a name="article-23004"></a>

### 第 23004 條【共有 Module】

共有 Module 不得僅因 Maintainer 只有一個螢幕，即視為僅有一個使用方。

<a name="article-23005"></a>

### 第 23005 條【Deprecation 通知】

依公開相容性承諾須提供遷移機會者，Deprecation 應給予合理期間。

<a name="article-23006"></a>

### 第 23006 條【交付驗收】

驗收應依約定標準，不得依事後發現對另一種藍色之偏好判定。

<a name="article-23007"></a>

### 第 23007 條【測試補償】

Bug 揭露測試缺漏者，當事方得以新增適當 Regression Test 作為工程爭議之和解方式。

<a name="article-23008"></a>

### 第 23008 條【維護界線】

志願者曾經貢獻者，不因此負有永久維護所有衍生作品之義務。

<a name="article-23009"></a>

### 第 23009 條【API 繼承】

替代 Service 非經確認相關相容性及資安條件，不得逕行繼承前身之信任。

<a name="article-23010"></a>

### 第 23010 條【爭議和解】

兩種競爭實作於評估期間得暫時並存，不因此宣告任一作者敗訴。

<a name="article-23011"></a>

### 第 23011 條【技術債到期】

延至下次 Sprint 之技術債應於該次規劃中可見，不得永久默默展期。

<a name="article-23012"></a>

### 第 23012 條【合理信賴】

依文件行為合理使用之 Consumer，不得僅因 Maintainer 事後後悔其設計而遭指控誤用。
