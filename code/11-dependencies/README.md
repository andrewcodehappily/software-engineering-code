<a name="article-14001"></a>

### Article 14001 — Dependency Citizenship

A package installed to solve one small problem may bring a population of transitive dependencies requiring registration.

<a name="article-14002"></a>

### Article 14002 — Lockfile Authority

A committed lockfile shall not be dismissed as decorative merely because it contains many unfamiliar names.

<a name="article-14003"></a>

### Article 14003 — Version Ranges

Permission to install a newer version shall not constitute proof that the newer version is compatible.

<a name="article-14004"></a>

### Article 14004 — Package Abandonment

A package without recent maintenance shall be assessed on its actual condition, not solely on the age of its last commit.

<a name="article-14005"></a>

### Article 14005 — Install Scripts

An installation script shall be granted no more trust than an equivalent script executed directly.

<a name="article-14006"></a>

### Article 14006 — Dependency Removal

A dependency may be repealed only after its remaining consumers have been located or reasonably ruled out.

<a name="article-14007"></a>

### Article 14007 — Version Zero

A package bearing version 0 shall not be exempt from the consequences of being deployed to production.

<a name="article-14008"></a>

### Article 14008 — Dependency Names

A package name differing from a trusted name by one character shall not inherit the trust of the original.

<a name="article-14009"></a>

### Article 14009 — Upgrade Hearings

An upgrade advertised as minor may be required to testify before the integration tests.

<a name="article-14010"></a>

### Article 14010 — Vendored Archives

Vendored code shall retain its origin and license even after it has been forgotten by its importers.
