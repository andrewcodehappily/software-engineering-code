<a name="article-20001"></a>

### 第 20001 條【估時條件】

工期估算之效力，以其所依據之需求為條件。

<a name="article-20002"></a>

### 第 20002 條【Scope 擴張】

連續提出之小需求，不得推定其合計仍為小幅變更。

<a name="article-20003"></a>

### 第 20003 條【Deadline 算術】

提前 Deadline 之行為，本身不減少尚未完成之工作量。

<a name="article-20004"></a>

### 第 20004 條【狀態顏色】

標示為綠色之 Project，不因此免除尚未解決之 Blocker。

<a name="article-20005"></a>

### 第 20005 條【會議產出】

會議持續時間不得作為已作成相應數量決策之證據。

<a name="article-20006"></a>

### 第 20006 條【Task 依賴】

受其他 Task 阻擋者，不得僅藉修改 Priority 標籤加速。

<a name="article-20007"></a>

### 第 20007 條【定義修正】

交付後變更完成之定義者，構成新需求，不得溯及認定原交付未完成。

<a name="article-20008"></a>

### 第 20008 條【Demo 例外】

Demo 成功者，不當然證明所有未展示之操作流程均已就緒。

<a name="article-20009"></a>

### 第 20009 條【Priority 通膨】

所有 Task 均被指定為最高 Priority 者，該指定即失去區別各 Task 之功能。

<a name="article-20010"></a>

### 第 20010 條【Project 復活】

已宣告永久取消之 Project 得重新啟動，惟不得將先前取消溯及改稱為計畫性暫停。
