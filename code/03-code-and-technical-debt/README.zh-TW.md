# 第三編　程式碼與技術債務法

[English](README.md) · [返回上層](../README.zh-TW.md) · [總目錄](../../README.zh-TW.md)

### 第 1024 條【歷史遺跡保護】

任何無人理解、無人認領，但刪除後將導致系統崩潰之程式碼，應列為受保護之歷史遺跡。

### 第 1025 條【註解效力】

當註解與程式碼之行為互相矛盾時，應以程式碼之實際行為為準。

### 第 2048 條【技術債務展延】

工程師得以「下個版本再處理」為由展延技術債務。展延次數不受限制。

### 第 4096 條【重構比例原則】

不得僅為刪除三行程式碼，而新增四個類別、六個檔案及兩項外部依賴。

### 第 1026 條【註解遺物】

僅以註解形式存續之程式碼，得移送 Git 歷史檔案館保存。

### 第 1027 條【命名程序】

變數命名所需之時間，不得推定與其名稱長度成正比。

### 第 4097 條【編譯警告豁免】

第一項　編譯期間所產生之 Warning，若未妨礙編譯完成，得暫予忽略。

第二項　前項 Warning 於日後導致程式崩潰者，工程師不得主張未曾受到警告。

第三項　Warning 數量不得作為判定程式能否執行之唯一依據。

第四項　凡以 `-Werror` 將 Warning 升格為 Error 者，視為編譯器進入戒嚴狀態。

涉及安全、資安、Undefined Behavior 或資料完整性之 Warning，不適用本條豁免。
