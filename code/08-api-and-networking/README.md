<a name="article-11001"></a>

### Article 11001 — Contractual Silence

An undocumented API response shall not become a contractual guarantee merely because it has occurred twice.

<a name="article-11002"></a>

### Article 11002 — Status Code Jurisdiction

A response bearing status 200 shall not conclusively establish that the requested operation succeeded.

<a name="article-11003"></a>

### Article 11003 — Timeout Appeals

A client awaiting a response indefinitely shall have the right to terminate proceedings after a reasonable timeout.

<a name="article-11004"></a>

### Article 11004 — Retry Proportionality

A failed request shall not be retried at a rate sufficient to create a second incident.

<a name="article-11005"></a>

### Article 11005 — Idempotency

A repeated request shall not acquire the power to charge a customer twice merely because the first response was lost.

<a name="article-11006"></a>

### Article 11006 — DNS Responsibility

DNS may be investigated before the application is rewritten in another language.

<a name="article-11007"></a>

### Article 11007 — Rate Limit Recognition

A client receiving status 429 shall not interpret the response as encouragement to try harder.

<a name="article-11008"></a>

### Article 11008 — Localhost Sovereignty

The address localhost shall refer to the machine making the request, not whichever machine the developer wishes it referred to.

<a name="article-11009"></a>

### Article 11009 — Versioned Treaties

An API breaking its published contract shall not escape scrutiny by renaming the endpoint.

<a name="article-11010"></a>

### Article 11010 — Cache Witness

A cached response may testify concerning the past but shall not be presumed to describe the present.
