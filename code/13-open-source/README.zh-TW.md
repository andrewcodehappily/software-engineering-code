<a name="article-16001"></a>

### 第 16001 條【授權審查】

Repository 公開可見者，不得解讀為其內容得無限制重用。

<a name="article-16002"></a>

### 第 16002 條【Maintainer 出勤】

Maintainer 不因公開 Repository 而負擔二十四小時服務義務。

<a name="article-16003"></a>

### 第 16003 條【Star 證據】

Star 數量不得作為正確性、維護狀況或實用性之決定性證據。

<a name="article-16004"></a>

### 第 16004 條【Fork 主權】

Fork 得成立獨立司法管轄區，惟仍應遵守前身之適用授權。

<a name="article-16005"></a>

### 第 16005 條【Issue 充分性】

僅記載「不能用」之 Issue，得退回要求補充具體事實。

<a name="article-16006"></a>

### 第 16006 條【Review 期限】

Pull Request 不得僅藉反覆詢問優先順序而取得優先權。

<a name="article-16007"></a>

### 第 16007 條【Upstream 外交】

Downstream 之修改，未經證明已為 Upstream 採用者，不得歸責於 Upstream。

<a name="article-16008"></a>

### 第 16008 條【貢獻者承認】

文件、測試及有用之 Bug Report，縱未新增可執行程式碼，仍得認定為貢獻。

<a name="article-16009"></a>

### 第 16009 條【封存 Repository】

已 Archive 之 Repository 不得推定死亡，其可能僅已完成立法任期。

<a name="article-16010"></a>

### 第 16010 條【Release 期待】

開源 Roadmap 於無實際協議時，不構成交付契約。
