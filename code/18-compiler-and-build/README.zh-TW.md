### 第 21001 條【編譯器證詞】

編譯器指向第 80 行，不足以證明第 80 行為犯罪現場。

<a name="article-21002"></a>

### 第 21002 條【分號失蹤案】

分號失蹤得引發後續大量 Error；不得逕將其各自認定為獨立罪行。

<a name="article-21003"></a>

### 第 21003 條【Clean Build 救濟】

Incremental Build 產物與原始碼紀錄牴觸時，得命重新 Clean Build。

<a name="article-21004"></a>

### 第 21004 條【Linker 管轄】

各 Translation Unit 均編譯成功者，不拘束 Linker 作成有利判決。

<a name="article-21005"></a>

### 第 21005 條【Build 期間】

工程師等待 Build 期間，不得僅為證明生產力而被要求啟動另一 Build。

<a name="article-21006"></a>

### 第 21006 條【平行編譯】

Build Job 數量應依可用資源決定，不得依 CLI 所接受之最大整數決定。

<a name="article-21007"></a>

### 第 21007 條【Warning 救濟】

Toolchain 升級後新增之 Warning，應先調查，不得逕歸責於應用程式行為之變更。

<a name="article-21008"></a>

### 第 21008 條【Debug 與 Release】

Debug Mode 獲判無罪之程式，仍得於 Release Mode 受審。

<a name="article-21009"></a>

### 第 21009 條【Build Cache】

Cache 產物非有來源證據，不得證明目前原始碼已經編譯。

<a name="article-21010"></a>

### 第 21010 條【目標架構】

Executable 不因複製至其他 CPU 架構即取得該架構之公民資格。

<a name="article-21011"></a>

### 第 21011 條【Compiler Flag】

以試誤方式新增之 Compiler Flag，應於其目的自集體記憶消失前予以記載。

<a name="article-21012"></a>

### 第 21012 條【Build 可重現性】

某工程師桌面存在 Binary，不足以證明 Build 程序可重現。
