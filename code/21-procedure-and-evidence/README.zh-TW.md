<a name="article-24001"></a>

### 第 24001 條【當事人適格】

受可重現 Bug 影響之使用者得提交 Issue，無須先取得法學學位或編譯器執照。

<a name="article-24002"></a>

### 第 24002 條【舉證責任】

主張變更提升效能者，應提出適當量測，不得以增加驚嘆號代替。

<a name="article-24003"></a>

### 第 24003 條【截圖證據】

截圖得證明可見行為，惟不足以單獨證明其內部原因。

<a name="article-24004"></a>

### 第 24004 條【最小重現】

Minimal Reproduction 應排除無關複雜度，不得刪除重現所指 Bug 必要之條件。

<a name="article-24005"></a>

### 第 24005 條【Log 證人】

不同機器之 Log 應依相關 ID 及時間資訊比對，始得採認其時間順序。

<a name="article-24006"></a>

### 第 24006 條【矛盾證詞】

兩名工程師觀測結果不同者，應先調查其環境，不得逕指控任一方說謊。

<a name="article-24007"></a>

### 第 24007 條【上訴程序】

已關閉之 Issue 得因重大新證據重新開啟，不得僅因再度渴望辯論勝利而開啟。

<a name="article-24008"></a>

### 第 24008 條【迴避】

作者得就自身爭議變更提供證據；可行時宜尋求獨立 Review。

<a name="article-24009"></a>

### 第 24009 條【證據開示】

證據請求應限於相關且適宜分享之資訊，不得擴及開發者電腦之全部內容。

<a name="article-24010"></a>

### 第 24010 條【程序和解】

爭議涉及文件契約而非程式缺陷者，得以修正文件解決 Issue。

<a name="article-24011"></a>

### 第 24011 條【缺席判決】

Issue 無人回覆者，不得視為同意所有提議變更。

<a name="article-24012"></a>

### 第 24012 條【終局判決】

已 Merge 之 Fix 得終結該案，但不免除未來版本之新案件。
